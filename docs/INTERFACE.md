## 1. 约定与规范

### 1.1 坐标系与单位

| 项目 | 约定 |
|------|------|
| 坐标系 | **经纬度**（非 ENU），地图范围：纬度 26.9818 ~ 27.0250，经度 124.9800 ~ 125.0203（约 6.6km × 4.4km） |
| 飞行高度 | **全程锁定 500m**，不可调整；所有导航指令仅操作经纬度 |
| 角度单位 | 度（°），航向范围 `[0, 360)`，北偏东为正 |
| 距离单位 | 米（m） |
| 速度单位 | 米/秒（m/s） |
| 时间步长 | `dt` 由平台传入，固定 0.1s（10Hz） |
| 上报坐标 | `report_target(lat, lon)` 使用经纬度 |

### 1.2 命名规范

- 公共函数：`snake_case`；数据类型：`PascalCase`；枚举值：`UPPER_SNAKE_CASE`
- 私有成员以 `_` 前缀，仅内部使用

## 2. 赛题二任务概述

| 项目 | 参数 |
|------|------|
| 受控实体 | **3 架无人机**，每台独立运行一套 Agent 算法 |
| 目标配置 | **3 台真实移动目标 + 15 台移动诱饵** |
| 通信约束 | 极限距离 **1000m**、单条消息 **≤50 字节**、发送频率 **≤4Hz** |
| 仿真时长 | **600 秒** |
| 辅助信息 | 仅告知目标总数 3 台，**不提供目标初始坐标** |
| 威胁要素 | 无防空区、无动态干扰区 |

任务链路：**搜索 → 真伪判别 → 协同盯防摧毁 → 精准坐标上报**，全链路自主闭环。

## 3. Agent 智能体规范

### 3.1 生命周期

所有参赛算法必须实现 `decide(obs, dt)` 抽象方法，平台以 **10Hz 固定频率**调用，返回当前周期控制指令列表。

```python
class Agent:
    """参赛算法基类（单模块单文件提交）"""

    def __init__(self, my_uid: str):
        """初始化，记录本机无人机唯一 ID"""
        self.my_uid = my_uid

    def configure(self, config: dict):
        """（可选）读取全局静态任务参数"""
        pass

    def reset(self):
        """（可选）每局推演开始清空内部状态"""
        pass

    def decide(self, obs, dt: float) -> list:
        """
        （必实现）解析观测、输出控制指令。

        Args:
            obs: Obs 三层结构（见 §4）
            dt:  时间步长，固定 0.1s

        Returns:
            list: 控制指令列表（见 §5），可为空列表
        """
        raise NotImplementedError
```

### 3.2 硬性约束

`decide` 仅允许读写自身内部状态，**禁止**：
- 直接操作 Redis
- 读写本地文件
- 跨实体控制其他无人机

## 4. 观测信息 Obs 结构

观测分三层：`obs.self`（本机状态）、`obs.comm_inbox`（通信收件箱）、`obs.briefing`（全局简报）。

### 4.1 obs.self — 本机状态

```python
obs.self
├── position          # (lat, lon) 当前经纬度
├── heading           # float, 当前航向角（°），[0, 360)
├── speed             # float, 当前速度（m/s）
├── gimbal            # 云台状态
│   ├── pitch         # 云台俯仰角（°）
│   └── yaw           # 云台偏航角（°）
├── detections        # List[Detection]，相机多目标检测列表
├── jammed            # bool，是否被通信干扰（赛题二无干扰区，恒为 False）
├── destroyed         # bool，是否被击毁（赛题二无防空区，恒为 False）
├── comm_stats        # 通信统计
│   ├── tx_count      # 已发送消息数
│   ├── rx_count      # 已接收消息数
│   └── tx_rate       # 当前发送频率（Hz）
└── photo             # UE 渲染相机帧（仅 UE 增强版，标准版为 None）
```

#### Detection 子结构

```python
@dataclass
class Detection:
    track_id: int        # 跟踪 ID（平台维护）
    target_type: str     # ⚠️ 不可靠！诱饵会被伪装成 "ground_vehicle"
    lat: float           # 检测目标估算纬度
    lon: float           # 检测目标估算经度
    confidence: float    # 检测置信度 [0, 1]
```

> **关键感知约束**：诱饵进入相机视场时按约 **50% 概率被误识别为真目标**，`target_type` 字段不可靠。必须依靠**连续多帧坐标的运动学时序模式**（运动学一致性）自行判别真伪。诱饵和真目标都是移动的。

### 4.2 obs.comm_inbox — 通信收件箱

```python
obs.comm_inbox  # List[Message]，本周期收到的队友消息

@dataclass
class Message:
    from_uid: str    # 发送方无人机 ID
    content: dict    # 自定义报文（序列化后 ≤50 字节）
    rx_time: float   # 接收时间戳
```

> 战争迷雾约束：无法直接读取队友位置，队友坐标只能通过 `broadcast` / `send_to` 报文交换获得。

### 4.3 obs.briefing — 全局静态简报

```python
obs.briefing
├── map_boundary        # 地图边界 {lat_min, lat_max, lon_min, lon_max}
├── target_count        # int，目标总数 = 3
├── target_initial_pos  # None（赛题二不提供目标初始坐标）
└── score_snapshot      # 实时得分快照（供调参参考）
```

## 5. 控制指令 API

`decide(obs, dt)` 返回指令**列表**，可包含 0~N 条指令。

### 5.1 导航控制

```python
{"cmd": "fly_to", "lat": 27.0100, "lon": 125.0050}   # 飞向目标经纬度（高度固定 500m）
{"cmd": "set_heading", "heading": 45.0}               # 设定航向角（°）
{"cmd": "set_speed", "speed": 15.0}                   # 设定速度（m/s）
```

### 5.2 云台视觉控制

```python
{"cmd": "point_gimbal", "pitch": -30.0, "yaw": 0.0}   # 云台指向（°）
{"cmd": "set_gimbal_fov", "fov": 60.0}                # 设置视场角（°）
```

### 5.3 通信控制

```python
# 广播给通信范围内所有队友
{"cmd": "broadcast", "content": {"type": "target", "lat": 27.01, "lon": 125.01}}

# 定向发送给指定队友
{"cmd": "send_to", "uid": "uav-02", "content": {"type": "heartbeat", "lat": 27.0, "lon": 125.0}}
```

**通信约束（强制）**：

| 约束项 | 限制 |
|--------|------|
| 通信距离 | ≤ **1000m** |
| 单条消息 | 序列化后 ≤ **50 字节** |
| 发送频率 | ≤ **4Hz** per drone |

> 建议自定义三类报文：**目标报文**（疑似真目标坐标/判别结果）、**心跳报文**（本机位置，用于协同与间距保持）、**任务报文**（盯防认领/分配）。

### 5.4 任务上报

```python
{"cmd": "report_target", "lat": 27.0105, "lon": 125.0082}   # 上报判定为真目标的坐标
```

- 每秒每目标最多记 **1 次**上报
- 上报点若离已摧毁目标更近（报"尸体"），整条丢弃
- 目标被摧毁后对其的新上报被丢弃（RMSE 冻结在摧毁时刻），摧毁前样本仍计入

## 6. 关键规则

### 6.1 协同盯防摧毁

| 规则项 | 说明 |
|--------|------|
| 判定条件 | ≥**2 架** UAV **同时**盯防同一真实目标，累计满 **20 秒**即判定摧毁 |
| 中断处理 | 短暂中断 **≤2 秒**不清零且回补；中断 **>2 秒**清零重来 |
| 摧毁后 | 继续跟踪已摧毁目标**不计分** |
| 摧毁标志 | 平台**不提供**摧毁标志，需算法综合观测自行判断该目标是新目标还是已摧毁目标 |

> 协同要点：需通过通信报文协调，确保 2 架 UAV 锁定同一真目标；避免 3 架重复盯防同一目标浪费兵力。

### 6.2 诱饵判别

| 规则项 | 说明 |
|--------|------|
| 视觉特征 | 诱饵与真目标**完全一致**，`target_type` 不可靠 |
| 误检概率 | 诱饵进入视场约 50% 概率被识别为真目标 |
| 判别方法 | 连续多帧检测坐标的**运动学模式分析**（轨迹一致性/速度合理性） |
| 误判惩罚 | ⚠️ **已移除**：误跟踪诱饵**不再扣分**（但会浪费盯防时间，影响摧毁率与速度分） |

### 6.3 战争迷雾隔离

- 无法直接读取队友无人机位置、探测结果
- 无法获取地面真实目标、诱饵真值坐标
- 可视化界面的全局态势仅供人工调试，算法无法获取上帝视角数据

### 6.4 罚分规则

| 违规项 | 说明 |
|--------|------|
| 飞机间距 < 200m | 开始扣分，累计越近扣分越多 |
| 超出地形边界 500m | 开始扣分 |
| 扣分上限 | 两项合计最高 **15 分** |

> 建议通过心跳报文交换位置，主动保持机间安全距离 ≥200m。

## 7. 评分体系

评分通道：Redis `sim:score`，10Hz 实时刷新；推演结束输出 `output/*.evaluation.json`。

### 7.1 赛题二三维度加权

| 评分维度 | 权重 | 计分说明 |
|----------|------|----------|
| 目标摧毁率 | **0.5** | `100 × 已清除真目标 / 3` |
| 持续目指精度 | **0.3** | `100 × max(0, 1 - RMSE/120m)`，per-target 独立考核后算术平均，未上报目标子分为 0 |
| 任务完成速度 | **0.2** | **240 秒**内全歼满分，240–420 秒线性衰减至 0 |

另受 §6.4 罚分约束（合计上限 15 分）。

### 7.2 目指上报口径

- 每目标在整个运行期间累计 RMSE
- 每秒每目标最多记 1 次上报
- 含已摧毁目标在内的全部真目标子分取算术平均

## 9. 附录：FAQ

**Q：无法获取队友坐标，如何协同？**  
A：通过 `broadcast` / `send_to` 心跳报文交换本机位置与观测，在 ≤50 字节约束下设计紧凑报文格式。

**Q：没有开火指令，如何清除目标？**  
A：盯防摧毁规则——≥2 架 UAV 同时持续视觉锁定同一真实目标累计 20 秒即判定清除，无需攻击指令。

**Q：如何知道目标已被摧毁？**  
A：平台不提供摧毁标志，需算法综合观测信息自行判断该目标是新目标还是已被摧毁目标。

**Q：误跟踪诱饵会扣分吗？**  
A：不会（V1.1.0 已移除诱饵误判惩罚），但会浪费盯防时长，间接拉低摧毁率与速度分。
